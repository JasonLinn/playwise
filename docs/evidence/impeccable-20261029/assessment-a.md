## 設計特異性 verdict

**有一致的作者意圖，也開始長出產品個性；目前最具辨識度的是「日常工作被理順」的互動，首頁外觀仍有設計工作室類別的可互換性。**

觀察：米白、橘紅、灰綠及深綠形成完整配色；襯線「有餘裕」與無襯線正文的混排、偏移的作品雙欄、線性服務表列、橘色聯絡區貫穿全頁。橘色線結呼應「把複雜理順」，流程示範又把這個抽象承諾轉成民宿、小店、接案三種日常。這比單純替模板換品牌名稱更具體。

主觀判斷：大字、留白、英文字眉、抽象線條與作品截圖的組合，換成另一間獨立數位工作室仍大致成立。「宜蘭出發」目前主要由文字與地址成立，沒有進一步成為內容選材或構圖規則。真正值得放大的特色是懂小型經營者的日常，而不是再增加視覺裝飾。

整體印象：令人願意看作品的工作室官網，視覺已經有基礎；下一步應補強「我這種問題適合哪個服務、看哪個證據、如何開始聊」的連接。沒有觀察到阻斷首頁主要操作的 P0/P1 問題。

## 值得保留的 3 個優點

1. **主題從畫面走進互動。** 首屏線結、文案「理順」與流程卡片從凌亂到排齊，共同傳達工作室想解決的問題。點擊後文案也跟著改變，不只是動畫。桌機 `desktop-hero.png`、`desktop-playground.png`，手機 `mobile-playground-open.png`。
2. **服務與合作語氣降低技術門檻。** 「不必一次改變所有事情」「沒有規格書，也可以開始」「特殊需求仍交給你判斷」明確承認小型生意的限制，沒有把自動化包裝成無限制承諾。`StudioHome.tsx:9` 起、`:235` 起；`WorkflowPlayground.tsx:7` 起。
3. **概念作品能沉浸，又有基本誠實邊界。** 首頁兩張主打卡和共用聲明標示概念；潮間首屏也標示虛構作品，bnb 首屏有三行性質說明及返回作品集。這些說明值得保留並提升可讀性，不能為更像真實旅宿而移除。

## 優先問題

### 1. [P2] 用於辨識與做決定的文字，被壓成了註腳尺寸

**觀察與證據：** 390px 寬時，主打作品「概念設計」為 9px、能力標籤與共用概念聲明為 10px，服務分類名稱為 11px、服務正文為 13px、服務 tags 為 9px；流程板卡片為 10px、諮詢準備區繼承 11px。首屏的裝飾圖則保留 310px 高。`studio.module.css:435`、`:598`、`:1009`、`:1079`、`:1092`、`:1095`、`:1133`、`:1136`、`:1175`。實際 DOM 讀值也確認 LINE LIFF 標籤為 9px、諮詢確認文字為 11px。見 `mobile-services.png`、`mobile-work.png`、`mobile-playground-open.png`。

**影響判斷：** Casey 在手機快速掃讀時容易只看見詩意標題，漏掉「做什麼、是否真實案例、實際如何合作」；這些內容不是單純裝飾性 metadata。這是可讀性判斷，不將小字直接宣稱為 WCAG 不合格。

**修正：** 手機將服務正文提高到約 15–16px，分類／概念標記／操作說明提高到 12–14px；裝飾性英文索引才保留小字。先重新分配 310px 線結圖及區塊留白，不必為放大字體讓整頁無限增長。維持現有色彩及標題風格。

**Impeccable 指令：** `/adapt`（手機閱讀層級），再 `/polish`（行長與節奏）。

### 2. [P2] 作品視覺重心偏向旅宿形象，自動化服務的證據太弱

**觀察與證據：** 桌機作品區約 1484px 高，兩張旅宿概念截圖分別占約 691 × 513px 與 553 × 487px；洗衣廠 LIFF／洗務通則只有末端約 93px 高的文字列。手機作品區約 1600px 高，兩張旅宿圖先後占據主要視覺，流程系統位於區域末端。三項服務都只有描述與 tags，沒有連到對應作品。`StudioHome.tsx:105` 起、`:168` 起、`:199` 起；`studio.module.css:296` 起與 `:389`。見 `desktop-work.png`、`mobile-work.png`、`desktop-services.png`。

**影響判斷：** 看得出能做漂亮旅宿網站，但想整理訂單或 LINE 流程的店家，需要自己把文字與作品連起來。這削弱「網站＋懂日常的系統」的雙重定位；不是斷言自動化能力不存在。

**修正：** 不必增加全部作品篇幅。保留一個主要旅宿展示，替一個流程作品提供同等可理解的畫面或 3 步操作前後示意；每項服務就近放一個「看相關示範」連結。加 1–2 句明確的問題與示範範圍，區分概念、展示與真實委託，不編造省時數字或客戶成果。順便將 bnb 在首頁也標為概念，與內頁一致。

**Impeccable 指令：** `/clarify`（能力與證據連接）、`/bolder`（突出流程作品）。

### 3. [P2] 想開始諮詢的手機使用者，需要離開目前閱讀脈絡找入口

**觀察與證據：** 首屏唯一內容 CTA 是探索作品，LINE 沒有直接入口；手機選單收起且 header 為 `position: relative`，閱讀途中不跟隨。三個服務列沒有行動連結。直接 LINE 可在流程示範的折疊區找到，或到末端聯絡區；本次展開諮詢區後，聯絡區起點約 document y=6187，整頁約 7056px。這是有展開狀態的量測，不能當預設高度。`StudioHeader.tsx:6`、`StudioHome.tsx:61`、`:203` 起、`:327`；`studio.module.css:62`；`WorkflowPlayground.tsx:129` 起。見 `mobile-hero.png`、`mobile-services.png`、`mobile-contact-detail.png`。

**影響判斷：** 已知道自己需求的訪客，讀到適合的服務時還要找下一步。既有主選單與下方連結提供替代路徑，所以不是任務阻斷，也不推論實際流失率。

**修正：** 在服務區結尾加一個就近的「聊聊我卡住的流程／網站需求」入口，帶到精簡需求準備內容或 LINE；首屏可增加低視覺權重的「已有需求？在 LINE 聊聊」。兩者擇適量實作，保留作品探索的主層級，不需要先增加整頁浮動工具列。

**Impeccable 指令：** `/clarify`（動作與去向）、`/adapt`（手機途中決策）。

### 4. [P2] 最終邀請有情緒，卻缺一小段具體的開始方式

**觀察與證據：** 聯絡區主訊息是「告訴我們，你想把時間留給什麼」，按鈕「在 LINE 聊聊」。合作流程說先釐清範圍、費用、時程；FAQ 費用題只列影響因素，沒有給訪客一個可直接照做的最小準備清單。實用的場景諮詢文字存在，但藏在前方流程體驗的折疊區。`StudioHome.tsx:291`、`:318` 起；`WorkflowPlayground.tsx:129`。見 `desktop-contact.png`、`mobile-contact-detail.png`。

**影響判斷：** Jordan 可能喜歡風格卻仍不知道該傳什麼；理性評估的小店老闆也不容易判斷下一步的投入。屬內容完整度問題，並非需要公開制式價格。

**修正：** 在 LINE 按鈕旁補一句「先傳現有網站／你在做的生意，以及最想改善的一件事；還沒有網站也可以」。若經營者確認可承諾，再加實際回覆方式或服務時間。把場景產生的諮詢模板連到末端入口，讓起手式不依賴先玩示範。費用保留依範圍評估，避免未經驗證的價格承諾。

**Impeccable 指令：** `/clarify`，必要時 `/onboard`（首次諮詢引導）。

## 情緒旅程

1. **到站：舒服、有餘裕。** 米白與橘線結確立個性，主標承諾自然。手機第一屏約 844px 幾乎都是 hero，尚未露出作品內容；對趕時間的人節奏偏慢，對探索型訪客則可能是合適的品牌鋪陳。
2. **作品高點：願意點進去。** 兩個旅宿畫面有情境與美感，是整頁第一個情緒高點。但讀者尚難判斷系統服務是否同樣成熟。
3. **服務低谷：從看圖轉成讀小字。** 有清楚分組，卻缺少能當場驗證說明的操作入口；手機要讀 3 組較長內容。
4. **互動回升：原來這是在講我的日常。** 前後狀態、可逆操作與現成諮詢文字，是最接近品牌主張的記憶點。沒有要求立即輸入個資。
5. **合作／FAQ：安心但資訊增量變小。** 語氣友善，先談需求、再報價、再交接；讀者對具體首次接洽仍留有疑問。
6. **結尾：邀請醒目，起手式不足。** 橘色聯絡區建立強烈結尾，電話及營業資訊提供基本安心感。若補上可照做的第一則訊息，會讓情緒更容易轉成行動。

## 可選後續方向（供 parent 最終提問使用）

1. **以手機諮詢為主：** 優先放大關鍵正文、補服務區行動入口與第一則訊息，保留目前藝術方向。
2. **以能力說服為主：** 給一個自動化作品完整的問題—流程—範圍展示，讓「懂日常的系統」取得與旅宿美感同等的證據。
3. **以品牌特異性為主：** 把三種日常的真實工作物件與流程用語發展成視覺素材，讓線結成為有脈絡的品牌系統；不先增加華麗動畫。
